# Как работаем над LASTLIGHT

`main` держим в состоянии, которое можно показать и запустить. Работу ведем в отдельных ветках и открываем PR, чтобы команда видела изменения до слияния.

1. Для каждой самостоятельной задачи создаем Issue и назначаем ответственного. В Issue фиксируем результат, который можно проверить. Распределение задач ведем там, когда команда его согласует.
2. Создаем ветку от свежего `main`. Названия по делу: `feat/camera-path`, `fix/scene-controls`, `docs/energy-model`.
3. Коммиты описывают последовательность работы. Один законченный шаг на коммит, без случайных названий и без смешивания чужих задач.
4. Открываем Draft PR после первого рабочего коммита. В описании пишем, что уже работает, как проверить, что еще осталось, и связываем PR с Issue. Изменения интерфейса показываем скриншотами или короткой записью.
5. Перед слиянием нужен зеленый CI и просмотр хотя бы одним другим участником команды. В `main` не делаем прямые пуши и не переписываем историю.

## Проверки

```sh
cd apps/web
npm ci
npm run build
npm run lint
npm run test:smoke
```

Браузерные тесты локально используют Chrome и сохраняют визуальные материалы. CI проверяет взаимодействия в Chromium без повторной записи видео. Для расчетного архива: `cd reference/legacy-physics`, затем `python -m pytest -q`.

Для визуальных изменений смотрим состояния на 1440 x 900 и 1920 x 1080. Для изменений физики проверяем единицы, границы батареи, энергетический баланс и происхождение входных данных. Синтетическую репетицию не подписываем как рассчитанный результат.

Не добавляем в репозиторий секреты, локальные файлы окружения, рабочие handoff-файлы и медиа без ясных прав на публикацию.
