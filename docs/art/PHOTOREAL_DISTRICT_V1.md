# LASTLIGHT / Photoreal District V1

## Goal
Transform the *existing* synthetic LASTLIGHT district into a credible architectural real-time 3D environment without changing parcel geometry, existing school identity, energy state machine, orbit controls, or blackout flow. This branch is a visual experiment. Keep the working version in `creative/issue-4-visual-kit-handoff` and `main` untouched.

## First implementation — residential architecture

**Actual WebGL code**, not AI video:
- `apps/web/src/scene/CityArchitecture.tsx`: mineral facade map (deterministic micro-grain, restrained concrete joints), world-space identical residential building mass instances, four-sided dark glass windows, thin frames, sill/lintel details, entries and modest balconies.
- `apps/web/src/scene/DistrictWorld.tsx`: replaces only the rendering of city building surfaces and decorates existing facades; all parcel positions/dimensions untouched. Existing lit window slots remain seeded in identical places, but are advanced slightly off the wall plane so the new dark glass doesn't hide blackout/restore emission.
- Instanced meshes preserve interactive fps; reduced-detail overlays omitted when lowPower mode is enabled.

## Original invariants
- District buildings generated from `parcelX`, `parcelZ` and the same seeded `buildings` array.
- Existing school origin `[13,0,7]`, school masses and **12 rooftop PV modules** unchanged.
- `CameraDirector.tsx` mouse orbit/wheel control, all preset shots and visible blackout/restore semantics unchanged.
- No new app or second 3D world. No AI promotional renders inserted into WebGL scene.
- Repeated flat shapes remain as underlying geometry — this pass targets convincing facades, not a verified photogrammetry model. Balcony projection increases exterior detail, **not building relocation**.

## Iteration 02 — Real streets (implemented in PR #15)

- `CinematicStreets.tsx` replaces the old one-color `Streets()` function.
- Preserves existing road centers `[-80,-33,55,100]`, exact 10-world-unit widths, original 270-unit lengths, and the surrounding parcels.
- Adds low-contrast tileable asphalt aggregate, pedestrian paving, curb upstands, faded road centerline dashes, and zebra crossings on existing intersections.
- Sidewalks **terminate at intersections** rather than bridging through the driving lanes.
- Uses a handful of reused procedural textures plus one instanced marking mesh to avoid exploding draw calls.
- Actual 1920×1080 WebGL frames (five-shot artifact) from [GitHub Actions 40107177049](https://github.com/pablo228sos/lastlight/actions/runs/40107177049). That run and companion Verify 40107177014 both succeeded for the original streets change. Subsequent camera QA refinements are on this branch and require their own new checks.

## Iteration 03 — Free camera navigation (implemented in PR #15)

- Left mouse drag: original orbit unchanged.
- Mouse wheel: original dolly zoom unchanged.
- **Right mouse drag or Shift+left drag: pan the existing camera and its target through the same world**, in the horizontal ground plane.
- No new map, buildings, teleportation or camera shot presets.
- `mission.spec.ts` adds a browser check that right-drag changes actual camera position without switching the district/phase.

## Screenshot integrity / important known pitfall

The first automatic captures checked camera *position* only. Real screenshots showed that camera pose and GPU buffer could still be stale. The feature branch now instruments actual camera **forward direction** and render-frame count, and `issue04.visual.spec.ts` waits for new rendered frames and validates both pose components. This is a QA change, not a cinematic change.

Do **not** label earlier before/after facility captures as perfectly registered if shot orientation was not recorded. The district building+streets side-by-side comparison generated from the canonical district shot is a reference for the new roads, but full frame-accurate acceptance awaits the latest verified camera test.

## What is not done

These are higher-quality *procedural* city facades and roads, not photogrammetry, 3D scans, or AAA asset replacements. A fully realistic district would also need believable adjacent land parcels, varied roof mechanical details, true glass reflections, facade decals, street furniture, higher-quality trees and genuine punctual lamp illumination. For the hackathon, prioritize the scene actually visible along the camera journey before filling unseen city blocks. AI-made reference videos should stay concept media and cannot substitute for interactable geometry.
