# Failure Frontier integration decision

This integration takes the bounded physical reference-map method from Askar's PR #7 at `7147b3f`, without merging its independent dispatch engine. The numerical source remains Beksultan's official Physics API v1 at `ef23a71` (`lastlight-dispatch-1.0.0`, schema `1.0.0`). The cinematic frontend comes from PR #8 at `92613f0`.

`POST /api/v1/frontiers` accepts a v1 scenario and bounded axes. It runs the official engine once at the longest horizon for each starting battery SOC. Each shorter cell is a prefix of that deterministic trace. A failure is classified inside a cell only when its event time is strictly less than the cell's exclusive horizon. A failure at exactly 9.12 hours is therefore not observed in a 9.12-hour run. Tests compare the map against separate official engine runs at the same coordinates.

The default map uses 13 SOC columns and 21 duration rows. It makes 13 physical calls to classify 273 cells. That call count is an algorithmic count, not a claim about ML speed. PR #7's published benchmark did not show ML-guided search beating its direct physical map.

PR #7's checkpoint was built against its own schema and engine 1.1.0, including demand-profile fields absent from the official v1 contract. The adapter does not load that checkpoint, does not accept arbitrary schema versions, and returns no ML proposals. `ml_status` and a warning state the incompatibility when ML is requested. A future ML release needs a reviewed v1 feature adapter, matched provenance, independent physics validation and a new benchmark.

The checked-in web map is generated by `physics_frontier(FrontierRequest())` and is labeled as an offline replay. Live mode calls the endpoint. The browser validator requires the exact official physics and schema versions, a complete verified grid, matching axes and no ML estimates.

The API's OpenAPI file was regenerated after adding the route. Existing simulation and comparison schemas, fixtures and engine equations were not changed.
